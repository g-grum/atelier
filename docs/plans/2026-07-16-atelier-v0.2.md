# Atelier v0.2 Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Atelier v0.2 — multi-projects (register any folder anytime, identity colors, per-project session counts, in-app unregister) and the usage gauges (5-hour window + weekly, honest local estimates with calibratable budgets, burn rate, "limite estimée ~HH:MM" forecast).

**Architecture:** Same four units as v0.1. The server gains one read endpoint (`GET /api/usage/history`), per-project session counts on `GET /api/projects`, and two calibratable budget fields on preferences (with a deep-merge migration). The web gains a pure usage estimator (the most-tested unit of this milestone), the gauges card, a permanent register-project affordance, and a projects section in settings. No SDK surface changes.

**Tech Stack:** unchanged (Bun, Hono, `@anthropic-ai/claude-agent-sdk` ^0.3.198, React 19 + Tailwind v4, Electron).

**Spec:** `docs/specs/2026-07-02-atelier-design.md` — normative, wins over this plan. Key spec anchors: "v0.2 — multi-projects + usage gauges"; "Usage & limits (honest data policy)": gauges and forecast are **local estimates** from the app's own usage events, **user-calibratable**, labelled « estimé » in the UI; window/weekly data comes from the `usageEvents` recorded since v0.1 (4 counters, 7-day retention).

**Conventions (identical to v0.1):** strict TDD; whole suite `bun test` green (baseline **261 pass**); `bunx tsc --noEmit` clean on apps/server, apps/web, apps/desktop; commits `feat:|fix:|test:|chore:` + trailer `(no trailer)`; tick your own task's checkboxes in THIS file in your final commit; French UI copy; amber exclusively for permissions. All commands from the repo root.

**State of the code this plan builds on (verified 2026-07-16):** the sidebar ALREADY renders multiple projects with color dots and per-project open/collapse (`SessionSidebar.tsx`), and `App.tsx` already keys the sessions query and draft creation on the open project. Do not rebuild those. What v0.2 adds is listed below and nothing else (YAGNI: no per-message model display, no activity panel — that's v0.3).

## Chunk 3: Web — usage gauges

### Task 3.1: Pure usage estimator (most-tested unit of v0.2)

**Files:**
- Create: `apps/web/src/state/estimate-usage.ts`
- Test: `apps/web/src/state/estimate-usage.test.ts`

The estimator is pure and takes `now` explicitly. Contract (exact):

```ts
import type { UsageEvent } from '@atelier/shared' // already lives in protocol.ts since Task 1.1 — do NOT move anything here

export type UsageEstimate = {
  /** 0..1+ share of the 5h-window budget consumed (may exceed 1). */
  windowRatio: number
  /** End of the current 5h block (blockStart + 5h), null when no active block. */
  windowResetAt: Date | null
  /** 0..1+ share of the weekly budget consumed over the trailing 7 days. */
  weeklyRatio: number
  /** Weighted tokens per hour over the trailing 60 minutes. */
  burnRatePerHour: number
  /** Projected instant the window budget is exhausted; null when burn is 0, no active block, projection lands after windowResetAt, or the budget is ALREADY spent (overrun is a state via windowRatio >= 1, never a past timestamp). */
  limitAt: Date | null
}

export function estimateUsage(events: UsageEvent[], now: Date, budgets: { windowBudgetTokens: number; weeklyBudgetTokens: number }): UsageEstimate
```

Model (document these constants in the module — everything here is an ESTIMATE, the UI labels it « estimé »):
- **Weighted tokens** per event: `input + output + cacheCreation + 0.1 * cacheRead` (`CACHE_READ_WEIGHT = 0.1` — cache reads are drastically cheaper against real limits; the calibratable budget absorbs residual scale error).
- **Blocks:** walk events chronologically; a block opens at the first event not covered by the previous block and spans 5 h. The current block is the last one if `now < blockEnd`, else none (this mirrors how Claude's 5-hour windows anchor on first activity).
- **Window:** weighted sum of events inside the current block. **Weekly:** weighted sum of events in `[now − 7 j, now]`. **Burn:** weighted sum in `[now − 1 h, now]`, per hour. **limitAt:** `now + (budget − windowSpent) / burnRate` when a block is active and burn > 0; null when the projection lands past `windowResetAt` (the window resets first) AND null when `windowSpent >= budget` already (the limit is hit, not forecast — the UI's overrun state comes from `windowRatio >= 1`, never from a past `limitAt`).

- [ ] **Step 1: Failing tests (≥ 11):** empty events → zero ratios, null reset/limit; single fresh event → block anchored on it, resetAt = at+5h; events 6 h apart → two blocks, only the second counts toward the window; weighting formula exact (event with only cacheRead 10 000 → 1 000 weighted); weekly includes events outside the block but inside 7 d; events older than 7 d ignored even if present; burn counts only the last hour; limitAt math on a crafted burn (e.g. budget 1000, spent 400, burn 300/h → now+2 h) — assert the timestamp; limitAt null when burn 0; limitAt null when projection > resetAt; **limitAt null when windowSpent >= budget even with burn > 0 (overrun is a state, not a forecast)**; ratios may exceed 1 (overrun keeps rendering). `UsageEvent` is imported from `@atelier/shared` (moved in Task 1.1).
